# Changelog

## Unreleased

### Added

- `viz --view context`, the system context diagram (Rust `View::Context`, Python `"context"`). The part usages of a context render as rectangles: its own, then those of its definitions (for a usage) or written generals (for a definition), with a redefined part drawn once; the part with the most connections is the centre (`<<system>>`, the first declared on a tie); each connector with two ends on two different parts is one edge labelled by its definition, else by its name. Ports stay off the diagram: an end attaches to the part its feature chain starts at. The centre's neighbours take `-up-` and `-down-` in turn, so the other parts form a row above and a row below it; stereotypes are hidden and a bold border marks the centre. The structured graph has no emitter for it (`GraphError::UnsupportedView`).

## v0.11.3

### Added

- `spec-refs/cbor-tables.json`, the CBOR codec tables as data for readers generated in other languages: the tables version, a digest of the four spec inputs, the kind names, the enum vocabularies and, per metaclass in type-code order, the compact and full field lists in ordinal order. `tools/gen_cbor_tables.py` writes it beside `cbor_tables.rs`, records the input digest there as `CBOR_TABLES_SOURCE_DIGEST`, refuses to regenerate over changed inputs without `--tables-version N` (so `CBOR_TABLES_VERSION` cannot stay behind a spec change by accident), and takes `--check`, which CI runs with the other generated catalogs. A test holds the file to the compiled tables.

- `DerivedValue::Literal(String)` and `DerivedValue::Literals(Vec<String>)`: the literal values the specification operations answer through `invoke_operation`, each in the spelling of the literal expression that would carry it (`3`, `2.5`, `true`, `"text"`, `*` for the unbounded natural; a quantity as `3 [kg]`): the one natural number of `MultiplicityRange::valueOf`, and the values of a model-level `evaluate` that are not elements (those answer references, as before). No property answers them. The `Integer` and `UnlimitedNatural` arguments of `MultiplicityRange::hasBounds` and `ControlNode::multiplicityHasBounds` are given as `Literal`.
- Deltas against a graph store's head. A client editing a model a store holds commits only its changes: Rust `Session::delta_cbor_from_store_head(head, portable)`, Python `Session.delta_cbor_from_head(head_json, portable=False)`, with `head` the store's head as it serves it (Python `Session.decode_cbor(data)` decodes an s2c snapshot to that element array, as WebAssembly `decodeCbor` does). Both sides are compared in the store's graph-normal spelling, so only real changes ship and the declared result digest is the one the store reconstructs; a strict delta carries the session's file layout.
- Deltas between two graph stores, for a push or pull: Rust `sysmlv2_cbor::store_delta_cbor(base, target)` and Python `sysmlv2.store_delta_cbor(base, target)` take the receiver's head and the sender's state as s2c snapshots. Both are graph-normalized and the target's ids rebased onto the base by ownership path, so independently derived states diff by structure. The delta is applied to the base before it is returned: when the rebase collides or its delta does not apply, the delta keeps the target's own ids. Rust returns a `StoreDelta` (`bytes`, `result_digest`, `fallback`) and Python `(payload, result_digest, fallback)`, where `result_digest` is the digest the receiver reports for its new head and `fallback` says why the rebase was not used, if it was not. The graph format is read from the snapshots' headers and the delta encoded in it; snapshots in two formats are refused, except that an empty base takes the target's.

### Changed

- Documentation: the evaluator's binding rule is written down (`eval.rs` header, API.md §4.2). Every feature evaluates with an effective value, inherited defaults included (SysML 8.4.4.11); when an inherited default fails to evaluate, the plain entry points fall back to the unbound value, which value hints, verdicts, the multiplicity checks and the solver rely on, and `evaluate_report` / `evaluate_in_report` with `into_checked_result()` are the entry points for a host that must not see a degraded value. The evaluator reads the parsed expression kept per feature value, not the Expression element tree (#62).
- Every transition usage owns the grammar's first empty `in` parameter, the slot of `Actions::TransitionAction::transitionLinkSource`, before its trigger payload, which is its second parameter (`inputParameter(2)`) and pairs with `States::StateTransitionAction::payload`; the lift writes nothing for it. The ids of the members written after it inside a transition (the trigger, guard, effect and their expressions) change.

Rust: `eval::UnitDisplay`, `ResolvedModel::value_as_written` and `ResolvedModel::render_value_in`.
- The structure graph's compartment rows carry the rows nested under them: a row whose element owns members that would be rows themselves (an attribute's nested attributes, `attribute dimension { attribute x; attribute y; }`) lists them as its `rows`, to four levels, in the same form as the card's own rows. The PlantUML emitter is unchanged and still prints the parent line alone.
- Check findings name the rule a semantic finding reports wherever they leave the toolkit: the language server publishes it as the diagnostic's `code`, the WebAssembly `check` and `Session.check` findings carry it as `rule` (absent when the finding names none), and Python's `Finding.rule` holds it (`None` when the finding names none).
- `verify` names the usage when a chain through one that declares no multiplicity (a part, item, attribute or port that a package owns, so a collection of any size) leaves a constraint undecided, and says to declare `[1]` on it, as the solver's reasons already did.
- `sysmlv2 convert --flexo` reads a JSON input the way Flexo MMS returns it, for `--to text`, `compact-json` and `full-json` alike: besides unwrapping the `{payload, identity}` change records and reading empty strings as null, it derives the `owningRelationship` and `owningRelatedElement` Flexo leaves out from the owners' `ownedRelationship` and `ownedRelatedElement`. A nonempty back-reference the payload states is never changed; conflicting owners, missing in-document forward ends and cycles are refused before any repair. The bindings take the same as an option: WebAssembly `Session.fromInterchangeJson(json, bundle, snapshot, indent, true)` and `fromInterchangeJsonWithPreparedLibrary(json, library, indent, true)`, Python `Session.from_interchange_json(json, lib, flexo=True)`. Rust: `sysmlv2_transform::unwrap_flexo` (now public, returning `Result<Value, LiftError>`) and `sysmlv2_model::lift::complete_owning_references` (returning `Result<usize, LiftError>`). `lift::validate_ownership` checks a payload's ownership without changing it, and `lift::from_compact_json_with_dialect` lifts in a dialect the caller names (a restored unit's file extension, say), which takes precedence over the root's recorded file name and metaclass inference; text that dialect cannot represent is refused.

### Changed

- A hover over a quantity value that reads differently in the units it was written in shows that reading too: `= 0.127 [m/s] (as written: 5 [in/s])`, or `= 5 [in/s] (SI: 0.127 [m/s])` with `valueHintUnits: "asWritten"`.
- Diagram graphs (`toGraph`, `sysmlv2 viz`): a usage node carries the ports it has through its definition as port nodes of its own in the structure tree as in the interconnection view (`kind: "port"`, `inherited: true`, an id under its parent's — `<parent>~<port>` — with the definition port's identity, so a rename or reveal acts on the definition), and every port node carries the ports nested in it: its own, and the ones through its definition, to a bounded depth. A structure-tree port usage node carries its `direction` and `conjugated` fields as an interconnection chip does. Connector ends project through nested copies, so `connect tank.bank.hot to …` ends on the copy of `hot` under the copy of `bank` on `tank` instead of stopping at `bank`. The standard library's ports on its abstract base definitions (`Ports::Port::subports`, …) are not copied.
- Rust: `sysmlv2_transform::CheckFinding` carries the finding's rule as `code` and is now `#[non_exhaustive]`, so later fields do not break callers again. Only the crate builds one: building it with a struct literal, or matching it without `..`, no longer compiles.
- A product, quotient or power of quantities is written in SI-coherent units: mass in kilograms rather than grams (the standard library defines `kg` as the gram with the `kilo` prefix), with the number divided by 1000 per power of mass, and SI's newton, pascal, joule and watt by name. `2 [kg] * 3 [m/s**2]` is `6 [N]` (was `6000 [g*m/s**2]`), `10 [N] / (2 [m**2])` is `5 [Pa]` (was `5000 [g/(m*s**2)]`), `10 [N] * 2 [m]` is `20 [J]` (was `20000 [g*m**2/s**2]`; a torque has the joule's dimension and is written `J` too), and `1000 [kg] / (1 [m**3])` is `1000 [kg/m**3]` (was `1000000 [g/m**3]`). The result is now the same unit as a bracket that spells it (`[N]`, `[kg*m/s**2]`), so adding one keeps the number as it is. Comparisons answer as before. Every surface that shows such a value changes with it: the language server's inlay hints and hovers (in the native server and the WebAssembly `LspServer` alike), `sysmlv2 eval`, and the values the WebAssembly and Python bindings return. A user unit named `g`, and a fractional power of mass whose factor has no exact root (`sqrt(4 [g])`), are written as before.
- Rust: `Value::Unbound` and `Value::UnboundMember` carry a second field, a `Via` naming the instances the feature is read for (`Via::instances`, `Via::is_declared`). Patterns need the extra field (`Value::Unbound(e, _)`), and a constructed placeholder passes one (`Via::default()`).
- A chain through a feature that stands for an exact number of unknown instances repeats a data member's value once per instance, read for the instance the chain reads it through: with `part motors : Motor[4];` and `mass = 0.55`, `sum(motors.mass)` is `2.2` instead of indeterminate, and an instance's redefinitions by name apply, spelled or by name alone (`drone : Quad { attribute :>> each = 0.6; }` and `part def Heavy :> Quad { attribute each = 0.6; }` give `2.4`), including in a calculation the definition declares and through nested instances, and its count reads the instance's bounds (`part counted : Motor[n];` with `:>> n = 6`). Anything else stays indeterminate, such as an element result, a feature of open count, a feature naming some of the instances (`part m1 :> motors[1] { … }`, wherever inside the instance it is declared), a reference, a binding whose ends do not both resolve, a redefinition under another name (`attribute weight :>> mass = 1.0;`) in the instance or in the type of the part read, a feature subsetting one that the instance redefines (`part frontLeft :> wheels;` read for an instance that redefines `wheels`), or a qualified name reading the definition the instance stands for.
- A JSON payload whose owned elements omit the corresponding inverse ownership property is refused (`LiftError::OmittedOwnership`), before document splitting. Read such a payload with the `flexo` option above. Both modes refuse contradictory owners, missing in-document forward ends and cycles; owners outside the input remain valid for slices.

### Fixed

- Bindings are followed once per read: a group of features all bound to one another, which could take seconds or never finish, now answers at once. A binding to a feature whose value is unknown keeps the bound feature's default from applying, and a binding end the instance redefines under another name reads as unknown.
- A collection gathered from subsetting features counts features that subset the same single member once (`part also :> a[1]; part again :> a[1];` beside `part a :> items[1];` is one item, not two), and a member the instance hides with a same-named member of its own (`part a[1] { … }` or `part a :> items[1] { … }`) is gathered as that member, not as well as the hidden one.
- A unit whose `unitConversion` binds `referenceUnit` to a derived unit (`N`, defined as `kg*m/s^2`) or to a product of units (`m^3`) converts to it, as one bound to a base or prefixed unit does. Such a unit used to stay a unit of its own, which no other unit converted to: 137 of the 444 SI and US customary units in the standard library, among them `lbf`, `kip` and `ozf` (to `N`), `Btu_IT` (to `J`), `hp` (to `W`), `gal` (to `m^3`), `L` (to `m³`) and `'°'` (to `rad`), and the units defined from them (`'lbf/in²'`, `'ft⋅lbf'`). `1 [N] + 1 [lbf]` now gives `5.448222 [N]` instead of failing on different units, `1 [lbf] == 4.448222 [N]` is `true`, and `1 [ft] * 1 [lbf] / (1 [s])` is `1.3558180656 [W]` instead of `0.3048 [lbf*m/s]`. The quantity-bracket precedence lint names a reading whose dimensions match the bracket's in the units written, so `360 / n ['°']` still measures `1/°` rather than the `1/rad` a degree converts to.
- Rollups over exact counts of unknown instances refuse to repeat a declaration's value when an implicit same-name override changes the instance, or when a loaded library subsets or redefines the collection's members. Library preparation and snapshot restoration preserve those safeguards.
- Repeating data values checks the allocation budget before cloning their payloads, including nested strings, constructed data fields, quantity units, and large exact numbers.
- Diagram graphs retain concrete ports inherited from abstract domain-library definitions, including nested ports and their connector endpoints. Summary size estimates include port copies beneath collapsed or truncated containers, so `fullWithin` respects those nodes when choosing the full graph.
- A reference unit declared with a name but no short name (`attribute m;` as a `unitConversion`'s `referenceUnit`) no longer spells the results it reaches as `unit` (`0.127 [unit/s]` is now `0.127 [m/s]`), and an enum literal with only a short name renders by it instead of as `<element>` in value hints and hovers.
- A metadata usage in an `enum def` body (`@M;`, `@M { }`, `metadata m : M;`, `@M about a;`) is an annotating member of the enumeration, owned by an `OwningMembership` as in any other body, instead of an enumerated value typed by the metadata definition. `check` no longer rejects it with `EnumerationUsage must be typed by EnumerationDefinition`, the interchange form carries the `MetadataUsage`, and the enumeration's literals (its `enumeratedValue`, and the rows a diagram draws) are its enumerated values alone. Element ids are unchanged; the member and its membership change metaclass.
- `check --format json` reports the normative rule a semantic finding names in `rule` (`validateSatisfyRequirementUsageReference`, …) instead of null, so a consumer reads the field instead of parsing the message. `rule` stays null for a finding that names none, such as an unresolved reference.
- A release's `SHA256SUMS` lists the npm package tarball (`sysml-wasm-<version>.tgz`) beside the native archives, so the package can be checked with `sha256sum -c` like the binaries.
- A chain over several values keeps every value, since the `.` operator's source and target are nonunique: three parts weighing 10, 10 and 12 give `sum((a, b, c).mass)` = 32, where equal values used to collapse into one (22).
- `size`, `isEmpty`, indexing and chains over a feature whose multiplicity reads another feature (`part counted : Motor[n];`) read the bound in the instance the feature is read for: with `part hexa : Quad { attribute :>> n = 6; }`, `size(hexa.counted)` is `6` instead of the definition's `4`. A bound reading a feature the instance does not select (one of an enclosing part's) stays unknown instead of taking the definition's value.
- A feature with no value that an instance inherits, or reaches through a chain, reads the instance's redefinitions. With `part def Quad { attribute each default 0.5; part spare : Motor[1] { attribute :>> mass = each; } }` and `part drone : Quad[1] { attribute :>> each = 0.6; }`, `drone.spare.mass` is `0.6` instead of the definition's `0.5`. The same holds through an alias (`attribute s = spare;`), in a calculation the definition declares and the instance runs (`twice()`, `drone.twice()`), through nested instances (`sys.drone.spare.mass`), and for `eval Pkg::drone::spare::mass`. A name in the inherited declaration still resolves where it is written: a package-level feature beside the definition is not replaced by one beside the instance. A chain redefinition in an enclosing type applies wherever the feature is read for that path: with `a6 : A { attribute :>> b.kb = 9; }`, `a6.b.c.v` and `a6.b.twice` read `kb` as 9, as do a chain three links long, one in a definition's own body and one beside a redefinition of the part it runs through; a chain through a subsetting part (`part b1 :> bs[1]; attribute :>> b1.kb = 9;`) applies to `b1` and leaves `bs` unknown.
- Binding connectors are followed: a feature with no value of its own, or only a default, reads the other end of a `bind` whose end names it, in the instance (`part bound : Quad { bind each = six; }` makes `bound.spare.mass` and `sum(bound.motors.mass)` read `six`), in its definition, through a chain end (`bind q.each = z;` in an enclosing part) and from either side. Every binding naming the feature is tried, in any order, and the first with a settled other end gives the value; an inherited binding reads the instance's redefinition of its end; a multiplicity bound reads its feature through the binding too (`part items : Motor[n]; bind n = six;` counts six); bindings a library declares, and a model's bindings to features it inherits from a library, are followed alike. A default holds when no binding settles a value, a value that is no default is kept, and two unvalued ends stay unknown. Rollups through an instance with such a binding fan out instead of staying indeterminate. A chain of more than 64 bindings is refused with a budget error.
- A multiplicity bound that reads a feature of an enclosing instance is read there: with `part def Sys { attribute k = 5; part rack : Rack[1] { attribute :>> n = k; } }` and `part items : Motor[n];` in `Rack`, `size(sys.rack.items)` is `5` (and follows the instance's redefinition of `k`), where the definition's `4` was read.
- Two redefinitions of one feature that an instance inherits on different paths without one specializing the other (`part mix : H1, R1;` where `H1` redefines `each` by name and `R1` redefines it under another name), an ambiguous lookup past such redefinitions, or a redefinition under another name in a type the instance specializes, make the feature's reads indeterminate instead of reading the declared value.
- Rust: `collection_cardinality_report` reads a placeholder's bounds in the instance the placeholder was read for, as `size` does, instead of certifying the declaration's bounds; where the instance overrides them it answers `IncompleteProvider` rather than the declaration's figure.
- A member populated by subsetting features collects those a general declares as well (`part def Kit { part items : Motor[0..*]; part a :> items[1]; part b :> items[1]; }` gives `size(kit.items)` 2 for `part kit : Kit;`), read for the instance, with a general's member that the instance redefines read where the redefinition is.
- Evaluation over deep part trees is faster than before this release's evaluator changes: the fan-out guard's checks run only while a fan-out evaluates its one instance.
- Features that specialize a member populate it only when they can supply every value it needs: with `part motors : Motor[4];` and `part m1 :> motors[1];` in an instance, `size(motors)` is `4` and `motors.mass` reads every motor, where `m1` used to stand for the whole collection (`size` 1).
- `eval Pkg::part::attr` evaluates `attr` for one instance of `part` whatever `part`'s multiplicity (but `[0]`), so a part that a package owns without a multiplicity no longer gives an indeterminate `Pkg::part::attr` while `Pkg::part::sub::attr` has a value. The CLI guide's `eval` example declares the `[1]` its chain `car.totalMass` needs.
- `sysmlv2 convert --to compact-json --flexo` unwraps Flexo change records on input, as `--to text` and `--to full-json` did; it failed with `element without @id`. `--flexo` with a CBOR target is accepted for JSON input (it reads the input's Flexo conventions; the CBOR carries the bare element array) and still refused for text input, whose JSON output it would wrap.
- JSON-to-text reconstruction refuses members that cannot be represented in the selected dialect instead of silently dropping them. Explicit unit and output filenames select the dialect before recorded root filenames and metaclass inference. Unnamed CLI directory exports and sessions use the lifted dialect's extension. Referenced identity-only stand-ins do not select a dialect; anonymous authored declarations are retained. Bare-object ownership edges and repeated IDs or edges no longer lose or duplicate declarations.
- A JSON payload lifts as KerML when it holds a `type`, or a feature, standalone relationship or multiplicity that a package or library package owns, or when its root is named as a `.kerml` file. Such a payload used to lift as SysML when nothing else in it was KerML-only. A placeholder row a producer writes for a reference it could not resolve (a `Classifier`, `Type`, `Feature` or `Namespace` with no owner, nothing owned and no name) no longer selects KerML, nor do the flags a full-form row spells at their defaults (`isAbstract: false`) or a derived reference to the row itself (`featureTarget`): a SysML payload with such rows used to lift as KerML and print KerML-only spellings (`composite`) that did not parse back. An anonymous multiplicity (`multiplicity [1..2];`, or a bound-less one an exporter writes as a usage's default) lifts in SysML, which parses it; only a named one is refused there.
- A session opened from interchange JSON names a document without a file name on its root `document-N.kerml` when it lifted as KerML (it was always `document-N.sysml`), so the KerML text parses as KerML instead of being refused (`document-1.sysml does not parse`).

### Upgrade notes

- Interchange JSON whose owned elements omit `owningRelationship` or `owningRelatedElement`, as Flexo MMS returns them, is refused (Rust `LiftError::OmittedOwnership`) where it used to lift flat into text that did not parse back. Both are owned, non-derived properties of the KerML metamodel, so a conformant compact payload carries them and reads as before. A caller reading Flexo payloads opts in to deriving them: `sysmlv2 convert --flexo`, WebAssembly `Session.fromInterchangeJson(…, true)` / `fromInterchangeJsonWithPreparedLibrary(…, true)`, Python `Session.from_interchange_json(…, flexo=True)`, or Rust `sysmlv2_transform::unwrap_flexo` before any `Session::from_interchange_json*`. Ownership that contradicts itself (two owners, a missing forward end, a cycle) is refused either way.
- A lift into SysML refuses, as `LiftError::Incomplete`, a member SysML cannot declare on its own (a standalone relationship, a named multiplicity or a `feature`, as at the top of an ownership slice), instead of printing KerML text that did not parse. Lift such a slice as KerML (`lift::from_compact_json_with_dialect`).
- A session opened from interchange JSON names a document whose root carries no file name `document-N.kerml` when it lifts as KerML (it was `document-N.sysml`); unit names are visible through `units()`.
- Combined quantities read in SI-coherent units (`6 [N]`, formerly `6000 [g*m/s**2]`), so code that parses evaluated values or hint text sees different units and numbers for the same quantity.
- Rust: `Value::Unbound` and `Value::UnboundMember` carry a second field, a `Via`; patterns need `Value::Unbound(e, _)`, and a constructed placeholder passes `Via::default()`. `sysmlv2_transform::CheckFinding` gains `code` and is `#[non_exhaustive]`, so a struct literal or an exhaustive match no longer compiles.

## v0.10.7

### Added

- The structured diagram graph marks nameless redefinitions: rows and nodes carry `redefining: true`, `chain` lists the link names when a feature chain is redefined (`attribute :>> chassis.mass` → `["chassis", "mass"]`), and `typeDerived: true` marks a label type that was not written, so a host can draw the borrowed name and the derived type as such.
- Two edit operations: `setRedefinedFeature` (Rust `EditBuilder::set_redefined_feature`) replaces the first written `:>>` / `redefines` target of a declaration in place, and `removeFeatureValue` (`EditBuilder::remove_feature_value`) removes a `= …`, `:= …` or `default …` clause. Both plan against the declaration's spans, so one batch can retarget a redefinition and change its value together.
- Rust `ResolvedModel` gains `value_is_default`, `redefinition_root`, `redefinition_spans`, `redefined_chains` and `chain_specialization_spans` for reading what an element redefines and whether its value is a default; the wasm session gains `valueIsDefault`, `redefinitionRoot` and `redefinedChain`.

### Changed

- A document symbol for an anonymous redefining usage (`attribute :>> chassis.mass : Real = 2;`) leads its detail with what it redefines, so an editor's outline tells one `«attribute»` from the next. The symbol's name stays the keyword; workspace symbols and completion are unchanged.
- Structure views and the diagram graph label a nameless chain redefinition by its chain (`chassis.mass : MassValue = 2.5 [kg]` where it read `= 2.5 [kg]`) and show the type it derives through what it redefines when none is written. A named target written beside a chain names the line instead, a chain with an unresolved link is not labelled by the links that resolved, and with inherited lines shown an inherited line is left out when one of the type's own lines reads the same name.

### Fixed

- On Windows, the standard-library cache lives under `%LOCALAPPDATA%\sysmlv2` (else `%USERPROFILE%\.cache\sysmlv2`) instead of being silently skipped when `HOME` and `XDG_CACHE_HOME` are unset. A run that finds no cache directory at all now warns once and prepares the library from source.
- `setFeatureType` (Rust `EditBuilder::set_feature_type`) writes a type on a nameless chain redefinition, after the chain's last link and ahead of any value (`attribute :>> chassis.mass = 2.5;` → `attribute :>> chassis.mass : T = 2.5;`); it was refused.
- `setFeatureValue` (Rust `EditBuilder::set_feature_value`) gives a value to a declaration that has a body and no value, ahead of the body (`attribute x { doc … }` → `attribute x = 3 { doc … }`); it was refused.
- A named feature that redefines a chain without writing a type (`part cb :>> chassis.body;`) is labelled with the chain's last link's type, derived, as a nameless one is.
- `validateFeatureValueOverriding` follows feature chains: `attribute :>> chassis.mass = 2.5 [kg];` overriding a bound (`=`, not `default`) value is now reported, as the nested `part :>> chassis { attribute :>> mass = 2.5 [kg]; }` form already was, so rewriting one form as the other no longer changes whether a model is valid. Either form also reports overriding a value bound by an inherited chain redefinition along the same path, naming it by owner and chain (`P::M2::chassis.mass`). Paths are compared by the features their links stand for, so a binding is found through subtypes, named redefining blocks and inherited blocks alike.

### Performance

- The checks enumerate inherited members with less repeated work: each feature's redefinition chain is walked once per state of the model instead of once per inheriting type, a base type's own members are collected once instead of once per specializing type, and a type whose own features neither redefine nor share a name with anything it inherits reuses the inherited members of other types on the same bases. The library's plan build reuses the snapshot's frozen lookup graph instead of building one, and a value-overriding finding that points into the library locates the overridden value by name and line index instead of re-parsing the library. Together, warm `sysmlv2 check --lib` runs 1.10–1.23× faster on every sample model (Apollo 11 252 → 218 ms, an 18.8 MB model 5.0 → 4.3 s), findings byte-identical.
- A prepared library carries its own static implied relationships (about 29,000 rows for the standard library) in its snapshot, so a session no longer materializes them for every model. The fixed cost of a session's first derived read drops by about half (a 34-element model 125 → 48 ms, the first `type` read 15 → 4–5 ms). The standard library's snapshot grows from 25.6 to 29.4 MB and decodes about 8 ms slower, once per process.
- The whole-library tables a session's planners read (names by qualified name, relationship owners, direct bases, the specialization graph and the validated library specialization rows) are built once and shared by every session on the same prepared library; a session builds only its own rows' share. The snapshot's kept lookup graph now covers the library's materialized rows too, so it is no longer rebuilt on every load (about 11 ms per process).
- A process that opens the same library directory again after its sessions closed reuses the decoded library instead of decoding the snapshot again (about 80 ms → 12 ms per open on a laptop). The two most recently decoded libraries are kept; `SYSMLV2_LIB_RETAIN=off` keeps none, and `prepared::release_retained_libraries` lets them go.
- A library directory's content key is answered from its file listing (paths, lengths, modification times) while nothing changed, so a later load in the same process skips hashing every file.
- A warm run memory-maps the standard library's snapshot where the target allows it (wasm, or a host that refuses the map, reads it whole as before) and decodes the facts and plans parts apart from the load: on threads of their own where threads are available, otherwise on first use, so a run that needs neither (a conversion, a diagram) never decodes them. A snapshot fed in chunks or held in memory still decodes every part with the load. A facts or plans part that fails to verify no longer refuses the whole snapshot: the run falls back to tabling or planning itself and removes the damaged cache file so the next run rebuilds it (a snapshot shipped beside the toolkit is left in place). The library's positional plans are read by row index instead of hashed into tables; the snapshot format is unchanged. Warm camera-example check 42 → 37 ms and conversion 34 → 30 ms on 16 cores, 70 → 65 and 60 → 49 on one thread (`SYSMLV2_THREADS=1`), about 4 ms less CPU per run, and no copy of the snapshot in a run's peak memory.

## v0.10.6

### Performance

- A model that declares a root name the standard library also declares at its root (`package <Requirements> 'Project Requirements'`, `part def Actions;`) no longer resolves the whole library again beside its own units on every run. Once the units are lowered, a build on the prepared library checks what each such name selects: while every one still selects the library's declaration, the prepared graph and plans stand, and only a declaration the lookup cannot tell apart from the library's (a `library package` of the same name, or for a library of one's own a root type or alias that lookup would select in the library's place) sends the model to the joint build. A 16-file model with two such packages checks in about 95 ms instead of 490 ms warm, findings and interchange output byte-identical. The sealed library snapshot, decided before lowering, keeps the conservative test.
- A warm run loads the standard library's snapshot on more than one thread. The snapshot is written as ten parts, each with its length and checksum in the header (format `SYSML-PREPARED-20`; every earlier snapshot is a miss and is rebuilt once), and a run with threads decodes and verifies the large parts side by side. A snapshot fed in chunks, as the browser kernel feeds it, reads the parts in order and now refuses a corrupt part before reading the next. The load takes 20 ms instead of 40 in process, and warm checks on a 16-core machine run 1.1–1.5× faster (the camera example 68 → 47 ms, the 28-file model 281 → 258), at about 10 ms of CPU and 8–11 MiB of resident memory per run. The cache directory's snapshot is also decoded while the library directory's content key is computed, and kept when the key agrees. `SYSMLV2_THREADS=1` runs the whole load on one thread, as a one-core machine or a wasm host does.
- A decoded snapshot's library plans are read back on a thread of their own, started as soon as the handle exists, so that conversion overlaps the model's lowering and resolution; the first request takes what the thread made, and a snapshot written from such a handle waits for it. Warm checks gain about 3–5% on models whose own build outlasts the conversion (the four-file vehicle example 137 → 131 ms, the 28-file model 284 → 277); the camera example is unchanged.

## v0.10.5

### Added

- `check` validates constructor arguments as the feature values they are. `new T(…)` binds each argument to one public feature of `T` — a positional argument the feature at its position in `T`'s own features (declaration order) followed by the inherited ones, a named argument the feature of that name — and reports an argument whose value can never conform to that feature's declared type (`new Iso8601DateTime(3)`: a number for the String-typed encoding) and an argument that rebinds a feature whose own value, or that of a feature it redefines, is not a default (`validateFeatureValueOverriding`, as for a written redefinition). It also reports a positional and a named argument landing on one feature, and a positional argument on a feature nothing can name (an invariant: a sequence meant as one argument). An argument past the features of the type and its written generals lands on an implied library base's feature and is not checked. A lambda body's trailing expression is checked in the body's own scope, where an argument bound through a body parameter is undecided. Rust `ResolvedModel::constructor_features` answers the sequence.
- Lint rule `literal-pattern` (warn by default): a string bound to a feature whose declared type carries a `StringPatterns::Pattern` annotation — on the type or a supertype, in its body or `about` it from another package — must match the annotation's regular expression in full, whether the string is a feature value, a constructor argument or a calculation argument. A value matching the annotation's broader `accepts` form instead reports at the `reduced` severity (info by default); the `patterns` option (configuration file only) supplies or overrides a pattern per qualified type name without touching a model, with backslashes doubled inside the JSON string as inside a SysML one. Rust `Config::literal_patterns`, `Config::literal_pattern_reduced` and `PatternSpec` expose the configuration.
- Ambient library `StringPatterns` (`local-packages/StringPatterns.sysml`), loaded beside `TransformMeta`: the `Pattern` metadata definition (`regex`, `accepts`, `form`) and its application `about` the standard library's `Time::Iso8601DateTimeEncoding`, whose format the standard library states only in documentation. `new Iso8601DateTime("1926-04-3")` is now reported (the day is not zero-padded, and the time and zone are missing); a date alone, such as `"1926-04-03"`, is accepted at the reduced severity, since ISO 8601-1 allows the reduced precision and the encoding's documentation does not.
- A rational without a terminating decimal expansion can be written five ways: `exact` (`1/15`), `approx` (`≈0.06666666666666667`), `overline` (`0.06̅`), `parens` (`0.0(6)`) or `unicode` (`¹/₁₅`, mixed as `2¹/₃`). Settings tune each style: significant digits, the longest repeating period written out, mixed numbers, the fraction slash, precomposed glyphs, and a digit limit past which a value falls back to an approximate decimal. Approximate decimals round on the exact value and take an exponent outside `1e-6`…`1e21`, so a value past the double's range no longer prints as `≈inf` or `≈0`. One spec string configures every surface: `--number-format` on `eval`, `query` and `verify` (witnesses and narrowed ranges) and on `lsp` (the server's default); the language server's `initializationOptions.numberFormat` (value hints, hover values and range hints); `setNumberFormat` on the wasm and Python language servers; the wasm `verify` option `numberFormat`; and the editor extension's `sysmlv2.numberFormat` setting. Every surface defaults to `exact`.
- Rust `numfmt::NumberFormat` parses and writes the spec and renders a `Rational`; `Value::to_string_with`, `ResolvedModel::render_value_as`, `WitnessValue::to_string_with` and `PropagateConfig::number_format` apply it, and `sysmlv2_lsp::run_stdio_with_number_format` / `run_with_number_format` start a server with a default format.
- `sysmlv2 prepare --lib <dir> --out <out>` writes a standard library's complete snapshot and resolution recording into a directory ahead of time, and a run whose cache has no snapshot for that library reads them from there in place — `<out>` given as `SYSMLV2_LIB_SNAPSHOT_DIR`, or a directory named `prepared` beside the executable — instead of preparing the library from source: the first check after an install takes what a warm one takes (the Camera example about 110 ms instead of 800 ms). Rust callers have `prepared::prepare_library_into` and `libcache::shipped_cache_paths`.

- Lint findings can be suppressed where they sit, in a note that names the rule: `// sysmlint-disable-next-line <rule>` above a line, `// sysmlint-disable-line <rule>` trailing it, or a `// sysmlint-disable <rule>` … `// sysmlint-enable <rule>` range (to the end of the file when nothing re-enables the rule), each listing comma-separated rule ids and an optional ` -- reason`; `//* … */` notes work the same way. Notes are not model elements, so a directive never enters the interchange form. Directives apply after every rule has run and change only what is reported: a suppressed site still counts in a rule's majority tally. The new rule `lint-directive` (warn by default) reports a malformed directive (an unknown verb or rule id, no rule named, an `enable` with nothing to re-enable) and one that suppresses nothing, with a deleting fix removing it; a directive for a rule the configuration turns off is dormant, not unused. Its `reason` option set to `required` also reports a directive without a reason. The text report closes with the count of suppressed findings, the JSON summary carries it as `suppressed`, and Rust `lint_outcome` returns the suppressed findings beside the reported ones; `directive::next_line_directive` and `directive::next_line_directive_rules` serve editors writing the next-line form.
- The language server offers every lint finding the quick fix "Disable `<rule>` for this line", which writes `// sysmlint-disable-next-line <rule>` above the finding at its line's indentation, or adds the rule to such a directive already there. It is never the preferred fix and never part of fix-all.

### Changed

- The expression evaluator binds a constructor's positional arguments to the instantiated type's public features in order, valued or not — the sequence `check` binds — instead of to the fields that carried no value: a defaulted field is now positionally bindable (`new Stamp("x", "month")` sets a `precision default "day"`), and an argument that would rebind a non-default value is an evaluation error, as it is a validation error. A library type whose later features are derived is affected: `new Collections::Array((2, 2), (1, 2, 3, 4))` now rebinds `rank` and is an error, where the old rule skipped it — name the fields, `new Collections::Array(dimensions = (2, 2), elements = (1, 2, 3, 4))`. A named argument for a private or protected feature is unresolved, as the rule binds public features only. The error for arguments past the features of the type and its written generals is unchanged.
- Editor value hints, hover values and range hints show a rational without a terminating decimal expansion as the exact fraction (`1/3`), like the command line, where they showed an approximate decimal (`≈0.3333333333333333`). Set the number format to `approx` for the previous spelling. The wasm `verify` report's `rangeApprox` follows the same default.
- Rust `PropagateConfig` has a second public field, `number_format`, which `FeatureRange::range_approx` (the display range) is rendered in, and is now `#[non_exhaustive]` so later settings do not break callers again: start from `PropagateConfig::default()` and use `with_max_iters` / `with_number_format` or assign the fields. Building it with a struct literal no longer compiles.

### Fixed

- Attribute and enumeration definitions implicitly specialize `Base::DataValue`, and attribute and enumeration usages implicitly subset `Base::dataValues`, as SysML requires. The implied-relationship planner named these bases as the Systems Library's `Attributes::AttributeValue` and `Attributes::attributeValues`, which are aliases of them, and found neither among the library's element names: the definitions got no implied base, and the usages fell back to `Base::things`, so a checked read of an attribute usage's `type` certified nothing and nothing a definition or usage inherits through the two bases was there (the compatibility `type` of the full form follows explicit specializations only and is unchanged). The bases are now named by their declarations. An attribute or enumeration usage's implied relationships are numbered in another order once its subsetting names the other base, so the identities of its implied typings change with it; the full-form corpus baseline records the new identities.
- A type that owns a feature and an alias of it passes both on. Its subtypes inherited neither Membership and lost the feature from their features, and a reference through either name in a subtype resolved only with the standard library loaded, by lookup paths that disagreed with the derived inheritance. The inheritance filters read KerML's `removeRedefinedFeatures` literally, so the alias and the owning Membership — two Memberships of one Feature, each in the other's redefinition closure — removed each other. Distinct Memberships of one Feature no longer remove each other anywhere (the projection reducer, the recorded-lookup projection, the builder's reducer behind the derived reads, and so the positional slots): a Feature's Memberships are removed only when another inherited Feature's closure reaches it or an owned feature redefines it, as the reference implementation and the previous release did. A multiplicity domain naming an inherited feature now keeps that feature and its value when the subtype declares an unrelated feature of the same name.

### Performance

- Checking a large model no longer plans the positional redefinitions of its types again for every budgeted attempt a check makes: a semantic pass plans them once up front, and an attempt that ran out of budget over a given state of the rows is remembered instead of repeated. The specialization closure of a type and the implicit-redefinition test the inherited-name check repeats are memoized per run, and the hot walks hash element indices with the id hasher. The largest converted model in the benchmark corpus checks in 9 s instead of 25 s with byte-identical findings.
- The prepared standard-library snapshot carries the library's own plans — the implied-specialization and positional plans every build on it extends — so a process reading the snapshot no longer plans the library again: a check of a small model takes about 150 ms instead of 235 ms, the Apollo model about 470 ms instead of 560 ms. The snapshot grows from 16 MB to 25 MB (gzip: 6.6 MB to 7.9 MB); its format is bumped, so the first run after the upgrade prepares the library once more. A handle writes its plans only when its own snapshot carried them or `make_plans` was called, so a build on a shared handle never changes what the handle writes.
- A reference that resolves to nothing no longer walks every scope its site reaches on every resolution pass: each scope keeps the set of names a lookup through it could find, and a lookup skips the bases, imports and recursively imported nested scopes that cannot provide the name. A model with a few hundred unresolved references and recursive imports of a large namespace resolves in 0.9 s instead of 7.1 s; the Apollo model checks 9% faster.
- The static facts the semantic checks read are made once per state of the rows and shared between the checks, instead of twice per pass: the largest converted model peaks at 1.6 GB instead of 1.7 GB.
- The inherited-name checks no longer compare every pair of same-named members a type inherits: a group of more than sixteen same-named members is decided owner by owner from the memoized specialization closure, and the collision check skips a name that cannot yield a reportable pair and stops at the first pair that is not cleared. The largest converted model in the benchmark corpus checks in 7.1 s instead of 8.0 s with byte-identical findings (pair comparisons 60 million → 0.3 million).
- The checksum over the prepared snapshot and a resolution recording, and the key over the library sources, fold eight bytes per step instead of one and do not depend on how the bytes are fed: a warm check of a small model takes about 125 ms instead of 150 ms. Every checksum changes, so the snapshot and recording formats are bumped and the library cache key changes with them: the first run after the upgrade prepares the library once more, and the previous cache files, named by the old key, are left behind.
- The prepared snapshot carries the frozen rows' structural scan with its typing and membership projections, so a process reading it no longer scans the library's rows again or projects their domains when a build first checks whether it may extend the library's plans; the membership projection itself keeps its claims in one arena instead of a set per row. A warm check of a small model takes about 105 ms instead of 125 ms, the Apollo model about 395 ms instead of 410 ms. The snapshot grows from 24.9 MB to 25.6 MB (gzip: 7.9 MB to 8.1 MB); its format is bumped.
- A run that finds no prepared snapshot of the standard library no longer waits for its cache files before it looks at the model: the resolution recording and the 25 MB snapshot are written on a thread while the model is built and checked, and joined before the process ends; the snapshot's header, string table and body are written one after the other instead of being joined in memory first. A cold run that cannot write its cache files says so after the verb's output rather than before it. A cold check of the Apollo model takes about 1.0 s instead of 1.14 s; a small model, whose own work is shorter than the write, stays within noise; a cold run's peak memory falls by about 22 MiB. `LibraryLoad` carries the pending writes (`finish` joins them and reports what could not be written; `PendingSave::detach` leaves them to the process for `finish_pending_saves`; a pending save dropped unfinished is joined), so a caller that ignores it reads complete files as before.
- The protected-membership access test a lookup runs no longer walks a scope's bases with a fresh visited set per query: each scope's transitive base scopes are made once per resolution pass and kept sorted beside the base cache, and the test is a binary search per enclosing scope. The largest converted model in the benchmark corpus checks in 6.45 s instead of 6.85 s with byte-identical findings.
- Every element row carries its metaclass index beside its name, so a test of a row's metaclass dispatches one name instead of two, or none where the general is known at compile time. A warm check runs 5–6% faster across the corpus (the largest converted model 6.49 → 6.18 s, the Apollo model 391 → 367 ms) with byte-identical findings.
- The inherited-member cache keeps each type's outcome trimmed to its length instead of with the slack its vectors grew with: the largest converted model peaks at 1.55 GB instead of 1.60 GB, the other converted model at 395 MiB instead of 427 MiB.
- The command line no longer frees a check's model and the shared library when the process is about to end, and the snapshot decoder looks a row's metaclass up once instead of twice: a warm check of a small model takes about 94 ms instead of 103 ms, the Apollo model 355 ms instead of 375 ms. Callers that run verbs in process (`sysmlv2_cli::run`) keep freeing everything; the binary opts in with `forget_at_exit`.
- An inherited-member enumeration no longer builds, grows and drops up to eight hash sets over the element rows for its own duration: the builder lends it scratch tables of generation stamps, so a set begins for free and marking an index is a load, a compare and a store. The largest converted model in the benchmark corpus checks in 5.68 s instead of 6.04 s, the Apollo model and the model with unresolved references 6% faster, with byte-identical findings and a few MiB more peak memory.
- The enumeration reads a candidate's declared name and short name with one search of its property row instead of two, and the walk feeding it reads a membership's visibility once per member instead of four times, once of them per comparison while ordering the members: the largest converted model checks in 5.45 s instead of 5.72 s, the other converted model in 1.08 s instead of 1.16 s.
- A test of an element row's metaclass against a literal name — some five hundred of them across the resolver and the checks — resolves the literal to its index while compiling (`is_a!`) instead of dispatching it through the generated name match at run time, and the owned-member read tests the hierarchy instead of hashing the type name: the model with unresolved references checks in 0.70 s instead of 0.77 s, the converted models 4% faster.
- The positional planner's tables — a type's direct bases, a planning's nodes, the redefinitions it reads and derives, its reduction's scratch sets, the library plans' tables and what a dynamic planning hands it — are keyed with the builder's id hasher instead of the standard library's default: the model with unresolved references checks in 692 ms instead of 716 ms, the largest converted model 2% faster, with byte-identical findings.
- The implied-specialization planner's graph, traversal marks and ranking, the membership context's guard tables, the import enumeration's visit table, the connector check's upward walk, the structural scan's unsatisfied ids and the facts' local id index use the same hasher: the Apollo model checks in 302 ms instead of 322 ms, the converted models 3–4% faster.
- A derived read of a feature-reference expression's names (`name`, `shortName`, `qualifiedName`) or of its owners (`owner`, `owningMembership`, `owningNamespace`, `owningType`, `owningFeatureMembership`, `endOwningType`, `isLibraryElement`) no longer makes the whole model's implied relationships first: those answers come from the expression's own row, its owners' rows and the naming rule. The read leaves the implied relationships to the next read that may depend on them — a derived read of another name, of any element, or a `property`/`derived_exact` read computed from them — which makes them first. On a freshly built session — what an editor holds after every edit — the first such read cost what making them costs, about 140 ms on a four-file model and 180 ms on a 28-file one in the wasm module, and now takes under a millisecond, so a host asking every element its name no longer pays for it on each analysis. A read of anything the expression owns or specializes (`type`, `result`, `ownedMembership`, …) still makes them first, and every derived and checked property answer is unchanged.
- The prepared standard-library snapshot carries its element table — metaclass kinds, ids, paths, property flags, owners, property keys and atoms, owned relationships and children — and the facts' index rows as columns the decoder reads in bulk, instead of a tagged value per field: the snapshot decodes in 35 ms instead of 48 ms, a warm check of the Camera example takes 83 ms instead of 95 ms and the Mass Roll-up example 87 ms instead of 99 ms, with byte-identical findings and 8–11 MiB less peak memory on the small models.
- The library's plans and the frozen rows' structural scan are columns too — index-keyed lists as a key, a length and a value column, pairs and flags as two columns and a byte each — and a column that does not cover its lists is refused as a plan that does not fit the rows was: the decode takes 28 ms, the whole load 43 ms instead of 64 ms, the snapshot is 23.6 MB instead of 25.6 MB; Camera checks in 75 ms, Mass Roll-up in 78 ms.
- An integer column widens into its vector in one pass per width instead of two passes through a word vector, and the decoder's shared-string pool hashes with the builder's id hasher: the decode takes 24 ms; Camera checks in 70 ms, Mass Roll-up in 74 ms, Apollo 3% faster.
- The snapshot carries the frozen library's recorded-lookup graph — nodes, Memberships, header bases, redefinition targets and the alias proofs' memoized projections — which a decoded library's freeze built from the rows again on every load, and reads it back when it fits the rows, every count, index and visibility checked: the freeze takes 6.5 ms instead of 12.4 ms and the whole load 34 ms, against 64 ms at the start of the round; Camera checks in 67 ms instead of 95 ms (1.42×), Mass Roll-up in 69 ms instead of 99 ms, the large models 1–3% faster, with byte-identical findings.
- The public property reads (`ResolvedModel::property`, `derived_exact`) share one kept checked row instead of making one per call: a receiver's complete type report, type features and usage-variability verdict are certified once and answer its later reads of `type`, `definition`, `isVariable`, `mayTimeVary` and the other type-dependent properties until the model, its closure policy or its planning state changes. On the Annex A vehicle model a second read of `type` costs 0.4 µs instead of 153 µs, of `definition` 0.8 µs instead of 166 µs, of `isVariable` 0.3 µs instead of 228 µs; the work allowance still starts over with every read.

## v0.10.4

### Added

- Lint rule `unit-precedence` (warn by default): a unit bracket on the right operand of `/`, `%`, `+`, `-`, `**` or `^` binds to that operand alone — `attribute c = 1 / 15 [km];` is `1 / (15 [km])`, a reciprocal length, where `(1 / 15) [km]` was meant. The finding names the binding and what the value measures instead; its fix parenthesizes the value (`--fix-semantic`, since it changes the value), with the written binding made explicit, `1 / (15 [km])`, as the alternative quick fix. `*` alone is exempt (both readings agree), a quantity on the left keeps the written binding (`2 * r + 20 [mm]`, `t / 900 [K]`), a sign on the magnitude is transparent (`1 / -15 [km]`), and an indeterminate operand stays silent. `dimensional-consistency` steps aside for an attribute the rule flags.

### Changed

- Rust `ConstraintInfo` carries `inherited`: whether its expression is a body declared on another element (a bodiless assert's definition, a closure type's constraint under a satisfaction claim) rather than the element's own result. `ResolvedModel::unit_of` answers which unit an element was built from, anonymous elements included.

### Fixed

- `unit-spelling` no longer reads constraint bodies in library units: a user `assert constraint c : D;` with no body of its own carries the body of its definition, and when `D` is a library definition that body was being spelled-checked, and its fixes aimed, in the library's unit. The same inherited body no longer counts once per usage either.
- `qualified-names`, `unit-spelling` and `unit-precedence` find the user units through every user element, so a unit holding only anonymous elements is linted like any other.

- `dimensional-consistency` no longer lets a bracket's unit name a quantity type of another dimension: the inferred type for `1 / (15 [km])` is a reciprocal-length type, not `LengthValue`, and the mismatch fix for `: LengthValue = 1 / (15 [km])` no longer proposes `LengthValue` again.

## v0.10.1

### Added

- Satisfaction claims are verified as a whole. Each `satisfy R by x;` gets one verdict, positioned on its statement: in `sysmlv2 verify` output (with the constraints behind a claim that is not satisfied listed under it), in the WebAssembly `verify` report's `satisfactions`, as a language-server code lens, and from Rust `check::satisfaction_claims`. A requirement's assumptions imply its required constraints and the requirements it composes, so a claim whose assumption fails holds vacuously, and a claim is undecided only when the known verdicts do not settle it. `not satisfy` inverts the verdict, and a requirement with no constraint to evaluate leaves its claim undecided.
- Rust `check::constraint_checks` returns the ordinary constraint verdicts over an already resolved model.

### Changed

- Quantity values evaluate sooner in models built on a prepared library. Preparing the standard library now records the dimensions of its quantity types and the expansions of its units (it had looked for the measurement unit type in the wrong package and recorded none), builds on the prepared library keep those records through every resolution pass, and an evaluation in progress reuses a unit's expansion unless a feature that expansion reads is being evaluated or overridden. On a model that imports the quantity libraries, the first inlay hint after an edit takes about a fifth less time and the first hover about a third less; preparing the standard library from its sources takes about 0.4 s longer.
- Hover, inlay hints, and code lenses answer sooner after an edit to a model built on a prepared library. A session derives the implied specializations and positional redefinitions of its own elements only, on top of those its prepared library derives once for its own; the language server's inlay hints and code lenses and WebAssembly `Session.verify` verify the session's resolved model instead of resolving the model again; and the typing, membership, and element-by-id indexes extend the prepared library's instead of covering every element again. On a model that imports the quantity libraries, the first hover or inlay hint after an edit takes a few milliseconds instead of a few hundred. An evaluation that ran out of steps deriving those relationships for the whole model may now complete.
- Inlay hints and code lenses answer sooner on models with satisfaction claims or calculations. A claim's subjects are read from the memberships of its requirement's types, and whether a calculation runs statements is answered through the specialization index, instead of scanning every element or every specialization, the standard library's included, on every verification. On a model that imports the quantity libraries, this takes about a third off the first inlay hint after an edit.
- Sessions on a prepared library build, check and plan sooner after an edit. The semantic checks pass over the library's elements and specialization rows without testing them; a session keeps the library's part of its lookup tables (per-scope lookup caches, relationship owners, specializations and multiplicities by element, chain redefinitions) instead of rebuilding it over the library's rows; its positional planning reads what the library's planning derived for the library's types instead of planning them again; and the inherited memberships of the library's scopes are read from the library's own build. On a model that imports the quantity libraries, a session builds in half the time, the WebAssembly `Session.check` takes about a third of the time, and the language server's first hover and first inlay hint after an edit about a third.
- `sysmlv2 verify` reports each satisfaction claim once, at its `satisfy` statement, instead of once per constraint at the requirement's constraint; the tally counts claims. A plain `constraint` member of a requirement is no longer part of the requirement's satisfaction (its `require` and `assume` members, assertions and nested requirements are).

### Fixed

- An unnamed usage that only references another feature (`satisfy R by x;`, `assert c;`) no longer answers a simple name. Two claims on a requirement declared in an enclosing namespace each resolve `R` to the requirement instead of to each other; a qualified path still reaches such a usage through the spelling it references.
- A claim that declares its own requirement (`satisfy requirement : R by x;`) is checked against `R`'s constraints; it was skipped.
- A valued redefinition of a feature chain (`attribute :>> chassis.mass = 2.5 [kg];`) supplies its value when the chain is read through the redefining part: directly, inside an inherited formula such as `totalMass = chassis.mass`, and from parts that specialize it.

### Upgrade notes

- `sysmlv2 verify` reports each satisfaction claim on one line at its `satisfy` statement (`SatisfyRequirementUsage, satisfies R by x`) instead of one `satisfies R` line per constraint at the requirement's constraint. The constraints behind a claim that is not satisfied follow it on indented lines that the tally does not count, so the tally counts each claim once. The WebAssembly `verify` report's `summary` now counts claims alongside constraints. Tools that read claim verdicts should read the claim lines, or the report's `satisfactions`.
- A plain `constraint` member of a requirement no longer takes part in a claim's satisfaction, so a claim that failed only on one of them may now be satisfied or undecided. Declare the member `require constraint` (or `assume constraint` for a precondition) to keep it in the check.
- Rust `VerifyReport` gains a `satisfactions` field, and `SatisfactionInfo` gains `unit`, `span`, `by`, `negated` and `nodes`. Code that constructs these structs or destructures them exhaustively needs updating.

The migration API converts complete legacy graphs with graph-derived IDs. Regenerate library snapshots and resolvers when changing formats; deltas do not migrate element identities.
- The default ID scheme changes from 1 to 2, changing freshly derived IDs for affected features and their descendants; persisted explicit IDs are preserved. Regenerate standard-library resolver artifacts. Scheme 1 ID-elided snapshots and deltas are no longer accepted; use an earlier toolkit to export explicit IDs before upgrading. CBOR scheme 3 carries canonical graphs, and format-aware readers reject incompatible artifacts.
- Checked properties, operations, and strict export cover supported semantic cases, not every specification derivation. Type-dependent properties no longer claim exact fidelity without complete evidence. Callers must handle typed refusals; best-effort readers remain available, and strict export is not a whole-model conformance check.
- The syntax tree's `ExprKind::BodyTerminator` variant is removed. The parser no longer reads a bare `;` as an expression body, so nothing produced it; drop matches on it. An empty expression body is `ExprKind::Body` with no members.
- Evaluation no longer takes every feature to be single-valued. A feature without a declared multiplicity takes the bounds shared by the features it subsets or redefines (a parameter or connector end also those it redefines by position; a bound that cannot be determined leaves it unknown). Failing those, attribute, item, part, and port usages owned by a definition or usage are `[1]`, and every other feature is `[0..*]`: usages a package owns, reference usages (including parameters written without a keyword, `in x : Real;`), and action, occurrence, requirement, and connection usages. A tuple containing such a feature, or a chain through one, now evaluates as indeterminate; declare `[1]` where a single value is intended for evaluation or solving.
- Text reports add a caret line under each finding's source line. Tools that read findings should use `--format json` rather than parse the text.
